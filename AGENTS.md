# Правила работы над модами FAF

Проект: моды для Supreme Commander: Forged Alliance Forever (FAF). Этот файл читают агенты, в том числе OpenCode и Claude Code.

## Общение

Участники проекта разбираются в разработке в целом, но не обязательно знают Lua, движок FAF и моддинг. Поэтому отвечай на русском и объясняй решения коротко и понятно: поясняй термины Lua и FAF при первом упоминании, при нескольких вариантах называй разницу и последствия, отделяй проверенные факты от предположений.

Если данных не хватает, скажи, чего именно. Не заполняй пробел догадкой.

## Структура

```text
AGENTS.md                     правила
My_mods/<проект>/             проект мода
    <Мод>/                    папка мода, в ней mod_info.lua
    tests/                    тесты, файлы test_*.lua
    tests/game/               сценарии для запуска в игре
    README.md                 описание мода
DOCUMENTATION/
    code_style.md             стиль кода
    knowledge/                проверенные факты о FAF
    tools/                    bootstrap.py, check.py, game_test.py и настройки проверок
    tools/game_mods/          тестовые моды для game_test.py
    tests/                    тесты инструментов
.claude/skills/               процедуры для агентов
references/                   исходники FAF и библиотек, только для чтения, в git нет
.tools/                       LuaLS, компилятор и Lua игры, в git нет
research/                     черновики, в git нет, источником правды не считаются
```

Перед первой работой запусти `python DOCUMENTATION/tools/bootstrap.py`. Локальные пути и установка мода описаны в `WORKSPACE_MAP.md`: его создают из `WORKSPACE_MAP.example.md`.

## Откуда брать факты

Не пиши функции, поля и поведение игры по памяти или по аналогии. Сверяй по источникам в таком порядке:

1. `DOCUMENTATION/knowledge/`.
2. `references/fa/`: код игры и описание API движка.
3. `references/ui-libs/`: API библиотек ReUI и UMT.
4. `references/lua-lang/`: особенности Lua игры.
5. Сторонние базы. Такой факт всегда помечай источником.

Как проверить факт: скилл `faf-verify-fact`.

| Задача | Что прочитать |
|---|---|
| Любой код на Lua | `DOCUMENTATION/knowledge/dialect.md`, `DOCUMENTATION/code_style.md` |
| Новый мод, `mod_info.lua`, `import`, установка | `DOCUMENTATION/knowledge/mod_structure.md` |
| Перехват функций игры, файлы `hook/` | `DOCUMENTATION/knowledge/hooks.md` |
| Контролы, окна, раскладка, команды | `DOCUMENTATION/knowledge/ui.md` |
| Юниты, категории, выделение, очереди приказов | `DOCUMENTATION/knowledge/units_and_categories.md` |
| Обмен данными между sim и UI, `Sync` | `DOCUMENTATION/knowledge/sim_ui_sync.md` |
| Настройки, `Prefs`, страницы настроек | `DOCUMENTATION/knowledge/settings.md` |
| Логи и ошибки движка | `DOCUMENTATION/knowledge/debugging.md` |
| Ресурсы и доход | `DOCUMENTATION/knowledge/economy.md` |
| Конкретный мод | `README.md` его проекта |

## Обязательная проверка

Задача завершена только после успешной команды:

```bash
python DOCUMENTATION/tools/check.py "My_mods/<проект>/<Мод>"
```

Если менялись файлы в `DOCUMENTATION/tools/`, дополнительно запусти `python -m unittest discover -s DOCUMENTATION/tests`. Если менялась база знаний, запусти `python DOCUMENTATION/tools/check.py` без аргументов: только так проверяются её источники.

- Вывод проверки приводится в отчёте.
- Нельзя отключать проверку, менять тест ради зелёного результата или подавлять замечание без написанной рядом причины.
- Ключ `--no-luac` существует только для CI, локально он запрещён.
- Если красный результат вызван проблемой вне задачи, это прямо указывается в отчёте.
- Если `check.py` просит запустить `bootstrap.py`, сделай это и повтори проверку.

## Проверка в игре

Стенд запускает мод в настоящей игре и сам выносит вердикт по логу:

```bash
python DOCUMENTATION/tools/game_test.py "My_mods/<проект>/<Мод>"
```

- Если изменение влияет на игру, запусти стенд и приведи его вывод в отчёте. Нужен компьютер с FAF: игре нужны окно и видеокарта, поэтому в CI стенд не работает. Если игры нет, напиши это прямо.
- Это единственный запуск игры, разрешённый агенту. Логи лежат в `.tools/game_test/`.
- Стенд ничего не пишет в игру и установленные моды: настройки и файл запуска временные, а моды подключаются из своих папок.
- Сначала идёт смоук-прогон только с UI-модами, как у игрока. Затем идут сценарии из `My_mods/<проект>/tests/game/`. Сценарию нужен вспомогательный sim-мод `ModTestSim`, потому что UI-мод не может создавать юнитов, а стенд проверяет, что в sim нет ничего другого.
- Новый сценарий запусти с `--only <сценарий> --without-mod`: без мода он должен упасть, иначе он ничего не проверяет.
- Стенд проверяет одиночный матч и передаёт игре программно клавиши без `Ctrl`, `Alt` и `Shift` и движение мыши. Игра запускается за другими окнами и фокус не получает. Внешний вид, сочетания клавиш, щелчки и перетаскивание мышью и матч с другими игроками считаются непроверенными, пока человек не подтвердил запуск. Если изменение влияет на них, напиши, что проверить.

## Закреплённые версии

Версии инструментов и исходников FAF закреплены в `DOCUMENTATION/tools/tool_versions.json` и сами не обновляются: новый код FAF может показать проблемы в модах. Чтобы поднять версию:

1. Измени значение в `tool_versions.json`.
2. Запусти `python DOCUMENTATION/tools/bootstrap.py`.
3. Запусти `python DOCUMENTATION/tools/check.py` без аргументов и разбери все новые замечания.
4. Если менялась версия `lua-lang`, поставь такой же тег образа `faforever/lua` в `.github/workflows/check.yml`.

## База знаний и документация

Документация описывает только текущее состояние. Журналы решений, история версий, отчёты о работе и отозванные выводы в репозиторий не пишутся: история есть в git.

- Перед задачей прочитай нужный файл из `DOCUMENTATION/knowledge/`.
- Новый проверенный общий факт о FAF добавь в `DOCUMENTATION/knowledge/` в той же работе. Формат описан в скилле `faf-verify-fact`.
- Если факт оказался неверным, исправь или удали его, а не дополняй рядом.
- Непроверенное в базу не пиши, кроме явной метки `Не подтверждено:`.
- Если изменение меняет поведение мода, обнови его `README.md` в том же коммите.
- Неочевидная причина в коде живёт коротким комментарием рядом с этим кодом.

## Границы

- Изменения делай только в рамках задачи. Находки вне её передай в отчёте.
- Не удаляй и не переименовывай файлы без просьбы.
- `references/` и установленные моды только для чтения.
- Установленную игру не меняем: FAF и Steam перекачивают её файлы, а мод должен работать на других компьютерах без правок игры. Подготовка для тестов живёт во временной папке.
- Чужой код копируй только после проверки лицензии и с сохранением атрибуции.
- Команды, которые перезаписывают установленный мод, запускает человек.

## Git

- Коммиты на английском, заголовок с маленькой буквы, без тела.
- Один логический шаг в коммите, но без дробления одной работы на мелочи.
- Новая ветка создаётся с `--no-track` и не отслеживает чужую ветку.
- Перед коммитом проверь `git status` и `git diff --cached`. Файлы добавляй по именам.
- В git не попадают игровые файлы, логи, резервные копии и локальные пути.
- `push` и другие действия на GitHub только по прямой просьбе.

## Отчёт

В ответе укажи:

1. Что изменено и зачем.
2. На какие источники опирается решение.
3. Какие команды запускались, что прошло и что нет.
4. Проверялось ли в игре: вывод `game_test.py` и что осталось проверить человеку. Если не проверялось, напиши это прямо.
5. Что осталось неподтверждённым.

Отчёт остаётся в чате, в файл он не сохраняется. Перед коммитом изменений в модах используй скилл `faf-review`.
